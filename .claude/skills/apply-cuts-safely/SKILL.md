# apply-cuts-safely — 컷 적용

승인된 스팬셋을 타임라인에 적용한다. **성공 여부는 판정하지 않는다** — 그건 `verify-cut-result`의 배타적 권한이다.

이 분리가 이 스킬의 핵심이다. 실행자가 스스로 "성공했다"고 선언하면, 도구가 `success: true`를 준 것만으로 통과 처리되어 부분 적용이 은폐된다. 실제로 그렇게 터진 버그가 이 프로젝트의 출발점이다.

## 1. 백업 — 원본은 절대 건드리지 않는다

`duplicate_sequence`로 사본을 만들고 사본에서만 작업한다. 원본 시퀀스 id에 변경 도구를 호출하는 경로는 없다.

## 2. 사본 id 확인 — 이름으로 찾지 마라

`duplicate_sequence`는 **이름 변경에 실패하고도 `success: true`를 반환한다**(알려진 결함). 응답의 `renamedAtProjectItem`이 `false`면 요청한 이름이 안 붙은 것이고, 사본은 Premiere 기본 이름("… 복사 복사")으로 생성된다.

그러므로 복제 직후 `list_sequences`를 호출해 **새로 생긴 id**를 찾아 확정하라. 이름으로 사본을 다시 찾으려 하면 원본이나 다른 시퀀스를 잡는다.

## 3. 적용 — 한 번에 한 패스

```
apply_timeline_removals(
  sequenceId   = 사본 id,
  removals     = 스팬셋 전체,
  sourceTimes  = 계획이 판정한 값,
  sourceMediaPath = sourceTimes가 true일 때 필수,
  rippleDelete = true,
  dryRun       = false,
  backup       = false   // 이미 1단계에서 직접 복제했다
)
```

**스팬을 쪼개 여러 번 호출하지 마라.** 도구는 스팬을 우→좌(늦은 시각부터)로 처리해 앞선 타임코드가 유효하게 유지되도록 설계돼 있다. 나눠 호출하면 첫 삭제가 나머지 스팬의 타임코드를 전부 무효화한다.

**계획 밖의 행동을 하지 마라.** 스팬셋에 없는 구간을 추가로 자르거나 임계값을 조정하는 것은 금지다. 계획이 틀렸다고 판단되면 실행을 멈추고 보고한다.

## 4. 기록 — 가공하지 않는다

응답 전문을 그대로 남기고, 실행 직후 `list_sequences`로 **실측 길이를 재조회**해 함께 기록한다. 도구가 보고한 길이가 아니라 시퀀스에서 다시 읽은 값이어야 한다.

`_workspace/02_operator_result.json` — 형식은 `.claude/agents/cut-operator.md`의 출력 프로토콜을 따른다.

응답 필드를 요약하거나 판정 문구("정상 적용됨")를 덧붙이지 마라. 검증자가 원시 데이터를 봐야 한다.

## 에러 핸들링

- **복제 실패** → 즉시 중단. 백업 없이 진행하는 경로는 없다.
- **`success: false`** → 원시 에러를 기록하고 중단. 재시도하지 않는다 — 원인 미상 재시도는 같은 실패를 반복하거나 타임라인을 더 망친다.
- **재시도가 필요할 때** → 부분 적용된 사본 위에 같은 스팬셋을 다시 적용하면 엉뚱한 구간이 잘린다. 사본을 버리고 **원본에서 새로 복제해** 처음부터 다시 한다.
- **불합격 사본은 지우지 마라.** 검증자와 사람이 열어볼 증거다. 삭제는 승인을 받는다.

## 테스트 시나리오

**정상 흐름:** 원본 539.17초 복제 → `renamedAtProjectItem: false` 확인 후 `list_sequences`로 새 id 확보 → 18개 스팬 1패스 적용 → 응답 전문 기록 → 재조회 실측 299.63초 기록 → 판정 없이 검증 단계로 전달.

**에러 흐름:** 적용 중 `success: false` → 사본 id·원시 에러 기록 후 중단 → 사본 보존 → 원본 무사함을 명시해 보고. 재시도 시 기존 사본 재사용 금지, 원본에서 새로 복제.
