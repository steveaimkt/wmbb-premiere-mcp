# 자막 검수 (편집본 기준)

**편집이 끝난(또는 편집 중간의) 타임라인을 읽어 자막을 만든다.** 컷편집과 독립적으로 단독 실행할 수 있다 — 사용자가 프리미어에서 직접 편집한 뒤 불러도 된다.

**트리거 "자막 검수 시작하자" → STEP A부터.** 각 STEP 끝에서 멈추지는 않되, **STEP A 검증에 실패하면 반드시 멈춘다.**

---

## 원칙

### 1. 재전사하지 않는다
원본을 **한 번만** 전사하고, 그 워드 타임스탬프를 편집본 타임라인으로 **재투영**한다.
편집을 몇 번 반복하든 이 방식이면 프리미어 실측과 **프레임 단위로 일치**한다.

재전사가 나쁜 이유(실측):
- 품질이 오히려 하락 — 이미 고쳐놓은 용어가 엉뚱한 말로 되돌아가고, 브랜드명이 띄어쓰기로 쪼개지고, 문장이 `"…된다."`처럼 중간에서 끊김
- 20분 재전사에 수 분 소요
- 손으로 쌓은 오탈자 교정이 전부 날아감

예외: 원음이 불분명한 **짧은 구간만** 원본에서 잘라 다시 들려 보는 것(slice ASR, 수 초)은 허용한다 — 깨진 문장 후보 확인, 잘린 목소리 판별용.

### 2. Whisper 단어 시각은 "어느 큐에 들어갈 말인가"까지만 쓴다
실측 오차 0.1~1.4초. 단어 끝을 무음 쪽으로 늘리고, 말 앞 필러를 다음 단어에 포함시키고, 길이 0 단어를 만든다. **큐가 화면에 뜨는 시각은 편집점(클립 경계) 프레임 또는 실제 소리의 조용한 지점으로 정한다**(STEP C-3). Whisper 시각을 그대로 쓰면 "복코 수술은 무조건"이 컷 지점(2.236초)보다 0.17초 늦게 뜨는 식으로 사용자가 바로 알아챈다.

### 3. 판정은 프리미어가 실제로 가진 값으로 한다
타임라인은 `list_sequence_tracks` 재조회, 올린 캡션은 저장된 프로젝트 파일(`read_sequence_captions`)로 대조한다. 도구의 자기 보고나 SRT 파일 자체로 "맞다"고 하지 않는다.

## STEP A — 타임라인 매핑 재구성 ★ (실패하면 여기서 멈춤)

```
list_sequence_tracks(sequenceId, includeSourceTimes: true)
```
클립마다 `startTime`/`endTime`(타임라인)과 `inPoint`/`outPoint`(소스)가 함께 온다.
**이 한 콜이 source→timeline 맵 전체다.**

```python
FPS = 30000/1001   # 시퀀스 값으로 (timebase 8475667200 ticks/frame = 29.97, 10584000000 = 24)
NEW = []; acc = 0
for cv, ca in zip(v1_clips, a1_clips):              # 타임라인 순서
    a, b = round(cv['inPoint']*FPS), round(cv['outPoint']*FPS)
    assert (a, b) == (round(ca['inPoint']*FPS), round(ca['outPoint']*FPS))   # V/A 소스 일치
    assert round(cv['startTime']*FPS) == acc                                  # 빈틈 없이 이어짐
    NEW.append((a, b, acc)); acc += b - a
assert abs(acc/FPS - verify['measuredEndSec']) < 1e-4   # ← 통과 못 하면 중단
json.dump({"fps": FPS, "map": NEW, "measuredEndSec": ...}, open("timeline_map.json", "w"))
```

- 클립이 100개를 넘으면 응답이 토큰 한도를 넘어 **도구 결과가 파일로 저장된다.** 그 파일을 스크립트로 파싱한다(`compact:true`는 첫/끝 클립만 줘서 맵을 만들 수 없다).
- `프리미어-컷편집`을 거친 시퀀스면 그때 적용한 계획(`removals.json`의 keep 프레임)과 **클립별로 일치하는지**도 본다. 일치하면 컷 적용 검증까지 겸한다.
- 미리 `timeline_map.json`을 저장해 두면 SRT 수정·재생성 때 다시 읽지 않아도 된다(단, 사용자가 그 사이 타임라인을 고쳤으면 다시 읽는다).

**길이 판정은 `verify.measuredEndSec`로 한다.** `list_sequences`의 `duration`은 편집 중 과도 상태를 반환한다(1352.75 → 1310.21 → 1279.67로 요동친 실측 있음).

`verify`에서 함께 확인:

| 필드 | 기대 | 아니면 |
|---|---|---|
| `contiguous` / `gapCount` | `true` / `0` | 타임라인에 구멍 — 자막을 만들지 말고 보고 |
| `avParity` | `true` | V/A 클립 수·끝이 다름 — 싱크 확인 요청 |
| `durationMatchesClips` | `true` | 프리미어가 아직 갱신 중일 수 있음. 한 번 더 읽어본다 |

> ⚠️ **사용자가 프리미어에서 동시 편집 중일 수 있다.** 값이 이상하면 **한 번 더 읽고** 판단한다. 편집 중 판독으로 "타임라인 손상"을 오보한 사례가 있다.

> ⚠️ **같은 이름의 시퀀스가 여럿일 수 있다** (`duplicate_sequence`가 이름 인자를 무시하고 `원본 Copy`를 만든다). 길이로 구분해 **ID로** 지정한다.

## STEP B — 전사 확보

우선순위:
1. `프리미어-컷편집`의 `_cutwork/sentences.json` — **단어 시각을 에너지로 바로잡은 값이 들어 있으므로 1순위.** 컷편집에서 delete로 판정한 문장(`decisions.json`)은 투영하지 않는다.
2. `analyze_speech_edit_points` 결과(`analysis.json`)
3. 둘 다 없을 때만 1회 전사:
```bash
ffmpeg -y -i "<mediaPath>" -map 0:a -c:a pcm_s16le -ar 16000 -ac 1 cut.wav
```
```
analyze_speech_edit_points(filePath: cut.wav, language:"ko", model:"small")
```
- **`model`은 `small` 이상.** `base`는 한국어 오프닝을 통째로 놓친다.
- 응답이 파일로 떨어지면 python 파싱. **이중 인코딩 JSON일 수 있다** — `json.loads(json.loads(raw))`.

## STEP C — 큐 조립

전체 절차·코드 → **`references/subtitle-pipeline.md`**

### C-1. 단어 투영 + 빠진 단어 처리

경계 유령(겹침 0.12초 미만이면서 단어 길이 40% 미만)을 버리고 투영한다. 그런데 **투영에서 빠지는 keep 문장 단어는 두 종류**라 구분해야 한다.

| 경우 | 판별 | 처리 |
|---|---|---|
| 컷이 실제로 그 말을 잘랐다 | 원본 그 근처(±1.5초)에 **잘려 나간 목소리 덩어리**(≥120ms)가 있고, slice ASR로 들으면 그 단어 | 자막에서 뺀다 + **컷 오류로 사용자에게 보고**(복구 여부를 묻는다). 실측: "원장님이" 1초가 잘려 질문이 "직접 하셨던…"으로 시작 |
| Whisper가 시각을 무음 쪽에 찍었다 | 그 단어 시각 범위에 잘린 목소리 0ms | **같은 문장의 앞 단어 끝(첫 단어면 다음 단어 시작)에 붙여 살린다.** 실측: "복코를", "돼요", "거죠", "거예요?", "있는데" |

- 잘린 목소리 판정은 **타임라인 전체**에서 한다(keep 문장 시간대 밖도). 첫 판정에서 문장 범위만 봤다가 "원장님이"(문장 시작 1.4초 앞)를 놓쳤다.
- 컷편집에서 의도적으로 뺀 소리(문장 앞 필러, 길이 0 "하지만" 자리)는 `cut_words`로 명시해 다시 살아나지 않게 한다.
- `inner-filler:<단어>`로 표시된 단어는 투영하지 않는다.

### C-2. 의미 단위 분할 (전체 최적화)

**20자(또는 25자)까지 채우고 넘치면 자르는 방식은 금지.** 사용자 지적: "얻기 / 위해서", "원하는 / 결과를"처럼 의미 중간이 끊긴다.
문장마다 **가능한 끊는 지점 조합 전체를 동적계획법으로 비교**해 비용이 가장 작은 것을 고른다.

- **문장(화자)이 바뀌면 반드시 끊는다** — 질문과 답이 한 큐에 섞이지 않게. 예외: 3자 이하 맞장구 문장("네", "그렇죠")은 혼자 0.2초 뜨므로 **뒤 문장 앞에 붙인다**.
- **끊기 좋은 곳(비용 0~1):** 쉼표 뒤, 종결어미(`다/요/죠/까`) 뒤, 연결어미(`~는데 ~건데 ~지만 ~니까 ~고 ~서 ~면 ~거나 ~는지 ~때문에 ~위해서 ~아니라 ~텐데`) 뒤, **원본에서 쉼이 있어 잘라낸 자리(컷 지점)**
- **보통(2.5~5):** 주제어(`-은/-는`이 꾸밈어미가 아닐 때) 뒤, 조사 뒤, 목적어(`을/를`) 뒤, 맨 명사 뒤
- **끊으면 안 되는 곳(8~9 + α):** 꾸밈어미(`하는/있는/원하는/했던/않는/할/한/의…`) 뒤, `~기 / 위해서`, `~하고 / 있는`(진행), `~해야 / 된다`, `~지 / 않는`(부정), `~면 / 좋을`(관용), `~다고 / 생각·봐`(인용), `점 / 하나`, 숫자 + `/ 이상·정도·만큼`, 큐 첫머리의 의존명사(`수/것/거/때/점` — **단어 전체가 그 글자일 때만**, `수술`·`중요한`·`때문에`를 잡지 않게), 큐 끝의 `NO_END`(`그·좀·이제·제일·많이·오래·다시·여러·이때…`)
- 큐 비용: 큐 하나당 기본 2, 짧은 줄(공백 제외 6자 미만) +4, 실제 노출 0.7초 미만이면 부족분 × 12, 긴 줄(18자 초과) 글자당 +0.4
- **실제 노출 시간 = 다음 큐 시작까지** (공백 0 규칙). 마지막 단어 끝까지로 계산하면 짧은 큐를 과하게 피한다.

### C-3. 큐 경계를 편집점·실제 소리에 맞춘다 ★

Whisper 시각으로 정하지 않는다(원칙 2).
1. 두 큐 사이(앞 큐 마지막 단어 시작 ~ 뒤 큐 첫 단어 끝)에 **컷(클립 경계)이 있으면 경계 = 그 컷 프레임.** 여러 개면 뒤 큐 첫 단어에 가장 가까운 것.
2. 컷이 없으면(연속 구간) 뒤 큐 첫 단어 앞 0.35초 ~ 뒤 0.15초에서 **실제로 가장 조용한 10ms 지점**(타임라인 시각 → 소스 시각 변환 후 원본 에너지). 그 지점 ±10프레임 안에 컷이 있으면 컷으로 맞춘다.
3. 첫 큐는 0, 마지막 큐 끝 = 시퀀스 끝 프레임.

실측(122큐): 경계 99개가 컷 프레임에 정확히 일치, 22개가 조용한 지점, 큐 안쪽 컷(문장 중간 쉼) 77개.

### 핵심 규격

| 항목 | 값 |
|---|---|
| 줄 수 | **1줄** (여러 줄 금지) |
| 글자수 | **띄어쓰기 뺀 25자 이하** (2026-11-15 사용자 지정. 처음 20자를 띄어쓰기 포함으로 셌더니 너무 잘게 쪼개졌다. 사용자가 다른 값을 말하면 그 값, 셈 방식도 확인) |
| 큐 사이 공백 | **0프레임** (끝 = 다음 시작) |
| 큐 경계 | 편집점이 있으면 **그 프레임에 정확히** |
| 노출 | 평균 2~3초, 최소 0.7초 지향 |

## STEP D — 오탈자 교정

공통 사전 → **`references/korean-typo-glossary.md`** (IT·비즈니스 채널 중심)
**영상 주제가 다르면(의료·뷰티 등) 프로젝트 전용 사전을 만든다** → `caption_glossary.json` (형식은 `references/subtitle-pipeline.md` §5).

**토큰 단위 1회 + 큐 병합 후 1회, 두 번 돌린다.**
> 병합 전에는 `"필히"`+`"이 거래명세서에서"`가 따로라 `"필이 이"` 규칙이 안 걸리고,
> 병합 후에는 줄바꿈이 끼어 `"바이브 코딩라면"`이 안 걸린다.

규칙 작성 시 함정(실측):
- **같은 토큰에 규칙이 순서대로 연쇄 적용된다.** `"맛없는"→"여기까지밖에"` 다음에 `"밖에"→""`가 있으면 방금 만든 "밖에"까지 지운다. `"환자"→"환자분은"` 다음 `"분은"→""`도 같은 사고. 삭제 규칙을 앞에 두거나 대체어가 다른 규칙의 대상 문자열을 포함하지 않게 쓴다.
- 짧은 문자열 삭제·치환(`"것들"`, `"밖에"`)은 **문장 ID로 범위를 묶는다** (`[잘못, 올바름, 문장ID]`). 안 그러면 "이것들이", "그런 것들을"까지 망가진다.
- 잔여 오탈자 검사는 범위 없는 규칙만 대상으로 한다.
- PowerShell `Set-Content -Encoding utf8`은 BOM을 붙인다 → JSON은 `utf-8-sig`로 읽는다.

**판단 불가한 건 추측으로 고치지 않는다.** 전사가 깨진 문장은 그 구간만 slice ASR로 다시 들려 후보를 얻고, 두 판독이 다르면 **사용자 확인 목록**(시각 + 두 후보)으로 넘긴다. 실측: "엉덩이만 안타깝지만 맛없는 것들 밖에" → slice 판독 "원장님은 안타깝지만 여성분들 밖에" → 확실한 부분("원장님은")만 확정, 나머지는 확인 요청.
명백한 오인식이 한 글자 섞인 경우(`숨시간`)는 그 글자만 빼고 보고한다.

교정 건수를 **종별로 로그**해서 보고한다.

## STEP E — QC (전부 0이어야 통과)

```
겹침 · 역순 · 길이0 · 시퀀스 초과 · 큐 사이 공백 · 여러 줄 큐 · 글자수 초과(공백 제외 25)
· 잔여 오탈자 · 어긋난 컷 · 말소리 위 경계
```
- **어긋난 컷:** 모든 컷 프레임에 대해 가장 가까운 큐 경계가 0프레임(일치)이거나, 10프레임보다 멀거나(큐 안쪽 쉼), 그 경계 자체가 다른 컷에 정확히 맞아 있어야 한다. 그 밖(컷 옆 1~10프레임에 컷이 아닌 경계)은 실패.
- **말소리 위 경계:** 컷이 아닌 경계 지점의 실제 레벨이 noise+12dB를 넘으면 쉼 없이 이어지는 말 한가운데를 끊은 것 → 그 자리는 C-2 규칙에 "붙어야 할 표현"으로 추가한다(실측: `않는 점 / 하나`, `있다고 / 봐야`).
- 마지막 큐 종료 = 시퀀스 끝 프레임.
- **저장한 SRT를 다시 읽어서** 큐 시작 프레임을 반올림·내림 두 방식으로 계산해 같은지, 컷 프레임과 몇 개 일치하는지 확인한다.

**전문 통독** — QC가 통과해도 큐 목록 전체(번호·시각·글자수·컷 일치 표시 `C`·문장 ID·텍스트)를 찍어 끊김이 자연스러운지 읽는다. 규칙 가중치를 바꾸면 다른 곳이 새로 나빠지므로(예: `해야` 앞을 비싸게 했더니 `한 번 / 이상`이 생김) **매번 전체를** 다시 본다.

## STEP F — 내용·흐름 리뷰 (요청 시)

자막 전문을 40초 블록으로 압축해 통독한 뒤 **채널 원칙(`CLAUDE.md` §1.5)**과 대조한다.

기계적으로 먼저 grep:
```
접근성 신호 : 비개발자 · 개발지식 · 코딩 몰라도 · 왕초보
CTA        : 구독 · 좋아요 · 댓글 · 링크 · 신청
리캡        : 정리하면 · 첫번째/두번째 · 요약
```
**0건이면 그 자체가 지적 사항이다.** 실측: 세 항목이 한꺼번에 0건이던 사례.

리포트는 **우선순위 + 타임코드 + 처방**. 잘라낸 구간에 해답이 있으면 복원 좌표(소스 TC)를 준다.

## 자막 파일 저장

- 경로: 프로젝트 `.prproj`와 **같은 폴더** (`get_project_info.path`)
- 이름: `<프로젝트명>_최종_<길이>.srt` (예: `260802 인터뷰_최종_21m20s.srt`, 길이 = `measuredEndSec`)
- **시각 기록 규칙 (프리미어 실측):**
  - 모든 시각은 정수 프레임 → 초로 바꾼 뒤 **밀리초를 올림**해 쓴다. 29.97fps 프레임 경계는 ms로 떨어지지 않아, 반올림하면 내림으로 읽는 쪽에서 1프레임 앞당겨진다.
  - **첫 큐가 0이면 `00:00:00,001`로 쓴다.** 프리미어가 정확히 `00:00:00,000`에서 시작하는 첫 캡션을 트랙에 놓을 때 떨어뜨렸다(가져온 항목에는 있었음).
  - **마지막 큐 끝은 내림**(시퀀스 끝을 넘지 않게). 올림한 끝값이 시퀀스 끝을 0.025프레임 넘자 프리미어가 1프레임 앞으로 잘랐다.
- **이전 버전은 지운다** — 단 **이번 작업에서 내가 만든 파일만.** 사용자가 이전에 만든 SRT가 프로젝트에 가져와져 있으면 지울 때 미디어 오프라인이 되므로 지우지 말고 정리 여부를 묻는다.
- 저장 후 경로를 보고하고, 요청 시 탐색기/Finder에 띄운다.

### 프리미어 캡션 트랙으로 넣기
`export_captions(importToSequence)`는 재전사 경로라 쓰지 않는다. 사용자에게 안내:
> 프리미어 `파일 › 가져오기`로 SRT를 불러온 뒤 프로젝트 패널에서 타임라인으로 드래그 (Start Point: **Timeline start** 또는 Source timecode)
> 같은 이름 SRT를 다시 만들었으면 **기존 캡션 트랙과 프로젝트 패널의 SRT 항목을 지우고 새로 가져온다** — 이전 내용이 남을 수 있다.

유튜브 업로드용이면 파일 그대로 올리면 된다.

### 올린 결과 검증 ("올렸어, 확인해줘")
1. 사용자에게 **프로젝트를 저장**해 달라고 한다(읽는 것은 저장된 파일이다).
2. `read_sequence_captions(sequenceId)` — 스크립팅 API는 새 방식 캡션 트랙을 못 보므로 저장된 `.prproj`를 읽는다(`source:"projectFile"`, `projectFileSavedAt` 확인 — 사용자가 저장한 시각 이후인지). 2026-11-15 이전 빌드의 MCP 서버는 이 경우 "0개, success"를 돌려주니, 그때는 MCP 서버 재연결이 필요하다.
3. 대조: 캡션 수 = SRT 큐 수, 큐별 시작·끝 프레임 = 의도한 프레임, 컷 정렬 큐 어긋남 0, 마지막 끝 = 시퀀스 끝. 빠진 큐는 시작 프레임 근접 매칭으로 찾는다.
4. 차이가 있으면 원인(프리미어 변환 규칙인지, SRT 값인지)을 보고 SRT 기록 규칙을 고친다.

## 자주 하는 실수

- **매핑 합계 검증을 건너뛰면** 조용히 어긋난 자막이 나온다. 반드시 assert.
- **`list_sequences.duration`으로 판정하면** 편집 중 값에 속는다.
- **타임코드↔초 변환을 암산하면 틀린다.** `83:03`을 `5043`으로 계산한 실수가 실제로 났다(`83*60+3=4983`). 반드시 코드로.
- **시퀀스가 여러 개면 대상을 ID로 특정한다.** 백업이 쌓이면 전부 `시퀀스 01 복사`·`원본 Copy`가 된다.
- **Whisper 시각으로 큐 경계를 정하면** 컷 지점과 0.1~0.5초 어긋나 사용자가 "시작이 안 맞는다"고 한다. C-3.
- **꽉 채워 자르면** 의미 중간이 끊긴다. C-2.
- **투영에서 빠진 단어를 전부 버리면** "복코를", "돼요" 같은 실제로 들리는 말이 자막에서 사라진다. 반대로 전부 살리면 잘린 "원장님이"가 소리 없이 자막에만 뜬다. C-1 표로 구분.
- **SRT 파일만 보고 "맞다"고 하면** 프리미어 변환(첫 큐 누락, 끝 1프레임)을 못 잡는다. 올린 뒤 프로젝트 파일로 대조.
- **Windows PowerShell에서 `python -c`에 한글을 넣으면 깨진다.** 분석은 `.py` 파일로. 콘솔 출력의 한글이 깨져도 파일 내용은 정상일 수 있다 — 결과는 UTF-8 파일로 써서 확인.
