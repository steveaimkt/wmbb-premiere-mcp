# 편집본 자막 생성 — 매핑 재구성 방식

> **재전사하지 않는다.** 원본 1회 전사(`analyze_speech_edit_points`)의 워드 타임스탬프를
> 타임라인 클립의 소스 in/out으로 재매핑한다. 편집을 아무리 반복해도 이 방식이면
> 프리미어 실측과 **프레임 단위로 일치**한다.

## 왜 재전사하면 안 되나

`export_captions(filePath, importToSequence)`로 편집본을 다시 전사해봤을 때(2026-08-03 실측):
- 품질이 오히려 하락 — 이미 고쳐놓은 용어가 엉뚱한 말로 되돌아가고, 브랜드명이 띄어쓰기로 쪼개지고, 문장이 `"…된다."`처럼 중간에서 끊김
- `importToSequence`는 **`Illegal Parameter type`으로 항상 실패** (캡션 트랙 0개)
- 20분 재전사에 수 분 소요

원본 전사는 이미 있고, 매핑은 산술이다. 재전사는 시간을 쓰고 품질을 잃는다.

---

## 1단계 — 타임라인에서 매핑 테이블 만들기

`list_sequence_tracks`로 V1 클립을 순서대로 읽고, 각 클립의 `get_clip_properties`로
`inPoint`/`outPoint`(= 소스 시각)를 얻는다.

```python
# NEW = [(src_start_frame, src_end_frame, timeline_start_frame), ...]
FPS = 24
NEW = []; acc = 0
for (src_in, src_out) in clips:            # 타임라인 순서
    a, b = round(src_in*FPS), round(src_out*FPS)
    NEW.append((a, b, acc)); acc += b - a
assert abs(acc/FPS - 시퀀스길이) < 1e-4     # ← 반드시 통과해야 함
```

**검증 실패하면 매핑이 틀린 것이다. 자막을 만들지 말고 멈춘다.**

### 클립 수를 줄이는 요령
`get_clip_properties`를 클립마다 호출하면 비싸다. 이전 매핑이 있으면
**ID·길이가 그대로인 클립은 이전 값을 재사용**하고, 새 ID/바뀐 길이만 조회한다.
클립 ID는 순차 hex(`000f436b`, `000f436c`, …)라 위치 추정에 쓸 수 있지만,
프리미어가 재사용/재번호하므로 **ID만 믿지 말고 길이로 교차확인**한다.

## 2단계 — 원본 세그먼트를 타임라인으로 투영

```python
for s in segments:                          # analysis.json (소스 시각)
    sa, sb = s['start']*FPS, s['end']*FPS
    iv = [((c+(max(sa,a)-a))/FPS, (c+(min(sb,b)-a))/FPS, min(sb,b)-max(sa,a))
          for a,b,c in NEW if min(sb,b) > max(sa,a)]
    # 타임라인에서 이어지는 것끼리 묶기 (컷으로 쪼개진 같은 문장 병합)
    # → 간격 < 0.06초면 같은 클러스터
    # 클러스터별 겹침이 0.35초 미만 AND 세그먼트의 40% 미만이면 버린다
```

두 가지 함정을 이 로직이 막는다:

| 함정 | 증상 | 처리 |
|---|---|---|
| **경계 유령 자막** | 컷 경계에 0.1초 걸친 단어가 자막에 뜸 (실제로는 안 들림) | 겹침 0.35초/40% 미만 제외 |
| **중복 출력** | 같은 문장이 두 번 나옴 (미세 pause 트림으로 세그먼트가 두 구간에 걸침) | 인접 클러스터 병합 |

**단, 콜드오픈처럼 같은 소스가 두 위치에 쓰이면 클러스터가 둘로 갈린다 — 이건 정상이고 각각 자막을 내야 한다.** 그래서 "구간별 emit"이 아니라 "클러스터별 emit"이다.

## 3단계 — 큐 조립 (1줄 · 20자 · 공백 0 · 문장 보호)

steve 채널 표준 포맷:

| 항목 | 값 |
|---|---|
| 줄 수 | **1줄** (여러 줄 금지) |
| 글자수 | **최대 20자** |
| 큐 사이 공백 | **0.0000초** (끝 = 다음 시작) |
| 노출 | 평균 2초 내외 |

### 문장이 잘리지 않게 — 사전 2개

```python
# 큐를 시작할 수 없는 말 (앞말에 붙인다)
NO_START = ("라고","라는","라며","라면","이라고","하면","하고","해서","되니까","되면",
            "때문에","니까","는데","지만","거든요","잖아요","습니다","입니다","거죠",
            "건데","든지","든가","면서","하는")

# 큐를 끝낼 수 없는 말 (다음 줄로 넘긴다)
NO_END = {"그","저","좀","뭐","이제","약간","사실","또","그리고","그래서","근데","그런데",
          "그러면","그럼","만약에","예를","왜냐하면","그러니까","아니면","혹은","일단",
          "이런","그런","저런","딱","막","되게","진짜","너무","제가","저는","어","아","음",
          "뭔가","한","이","그거","이거","저거","가장","더"}
```

**순서가 중요하다:**
1. 위 사전으로 **원자(atom)** 먼저 병합 — 붙어야 할 토큰끼리 한 덩어리로
2. 원자를 20자까지 포장. 문장 끝(`요/다/죠/까/?/!`)이고 9자 이상이면 거기서 끊음
3. 0.7초 이상 쉬면 강제 분리
4. 그래도 20자를 넘는 원자는 **토큰 경계에서 재분할** — 사전을 어기지 않는 지점만 선택, 없으면 단계적으로 완화
5. 마지막에 `cue[i].end = cue[i+1].start`로 공백 제거

### 개선 전후 (실측)
```
❌  전형적인 관공서 스타일 / 좀 가야 된다 / 라고 하면 수정 버튼 저장해가지고
✅  좀 관공서 스타일로 / 좀 가야 된다 라고 하면 / 수정 버튼 저장해가지고 열기 하면
```

## 5단계 — 오탈자 교정

`references/korean-typo-glossary.md`의 사전을 **토큰 단위로 먼저** 적용하고,
큐 병합 **후에 한 번 더** 문자열 치환한다.

> 병합 전에는 `"필히"`+`"이 거래명세서에서"`가 따로 있어서 `"필이 이"` 규칙이 안 걸린다.
> 반대로 병합 후에는 줄바꿈이 끼어 `"바이브 코딩라면"`이 안 걸린다.
> **양쪽 다 돌려야 잡힌다.**
