# 프리미어 컷편집 (단계별 게이트)

촬영본 하나를 **분석 → 카테고리별 제안 → 사용자 승인 → 삭제 → 검증** 순으로 다듬는다.
이 스킬의 핵심 산출은 "삭제"가 아니라 **분석값 전달**이다. 삭제는 사용자가 승인한 카테고리만 한다.

**트리거 "컷편집 시작하자" → STEP 0부터 순서대로. 자동으로 삭제까지 달리지 않는다.** 각 STEP 끝에서 멈추고 사용자 확인을 받는다.

**편집이 끝나면 자막은 `자막-검수` 스킬로 넘긴다.** 여기서 자막을 만들지 않는다.

---

## ⚠️ 판정 원칙 — 이 스킬의 1번 규칙

**도구의 자기 보고를 판정 근거로 쓰지 않는다. 판정은 재조회한 `verify`로 한다.**

변경계열 도구(`apply_timeline_removals`·`insert_clip`)는 실행 후 타임라인을 다시 읽어 `verify`를 붙인다:
```jsonc
"verify": { "measuredEndSec": 1279.667, "gapCount": 0, "contiguous": true, "avParity": true },
"verified": true, "verifyProblems": null
```
- `verified:false` 또는 `verifyProblems`가 있으면 **멈추고 보고.** 자동 복구·재시도 금지.
- `fullyApplied:true`·`inSync:true`·`shortfallSec:0`이 **전부 정상인데 27초 구멍이 남은** 실측 사례가 있다. 그래서 `verify`가 생겼다.
- **`list_sequences.duration`은 길이 판정에 쓰지 않는다.** 편집 중 과도 상태를 반환한다(1352.75 → 1310.21 → 1279.67 요동 실측).

> 사용자가 프리미어에서 **동시 편집 중일 수 있다.** 값이 이상하면 한 번 더 읽고 판단한다. 편집 중 판독으로 "손상됐다"고 오보한 사례가 있다.

## STEP 0 — 연결·대상 확인 + 촬영 유형 판별

`get_project_info` → `list_sequences` → `list_project_items`(mediaPath 확보).
`list_sequence_tracks(sequenceId, includeSourceTimes:true)`로 클립 구성과 소스 in/out을 **한 번에** 읽는다. 원본이 길고 타임라인이 일부만 쓰면 **그 구간만** 추출한다.

**촬영 유형을 반드시 묻는다 — 이후 판단이 갈린다.**

| 유형 | 특징 | 주의 |
|---|---|---|
| **솔로 강의·시연** | 재테이크 있음, longGap = 화면 시연 | `duplicates` 신뢰 가능 |
| **인터뷰·대담** | 재테이크 없음, 화자 교대 호흡이 리듬 | **`duplicates` 대부분 오탐** (STEP 2) |

→ 대상·길이·트랙 구성 + 유형을 보고하고 "이 시퀀스로 진행할까요?" 확인.

## STEP 1 — 음원 분석 + 자막 추출

```bash
ffmpeg -y -ss <inPoint> -i "<mediaPath>" -t <duration> \
  -map 0:a -c:a pcm_s16le -ar 16000 -ac 1 <scratchpad>/cut.wav
```
```
analyze_speech_edit_points(filePath: cut.wav, language:"ko", model:"small")
```
- **`model`은 `small` 이상 고정.** `base`는 오프닝 수 초를 전사 실패하고 그걸 인트로 무음으로 보고한다(후크 삭제 사고의 원인). `warnings` 뜨면 재실행.
- 결과가 토큰 한도를 넘어 파일로 떨어지면 python 파싱. **이중 인코딩 JSON일 수 있다** — `json.loads(json.loads(raw))`.
- **`진폭 기반 analyze_audio_edit_points`는 쓰지 않는다.** steve 촬영본은 노이즈 플로어가 −21dB라 임계값 2dB 차이로 결과가 폭주한다.
- **이 전사 결과(`analysis.json`)를 버리지 말고 보관한다.** `자막-검수` 스킬이 그대로 재사용한다.

## STEP 1.5 — 본편 시작점 탐지 ★

**촬영본 앞부분이 통째로 준비 구간일 수 있다.** 실측: 92분 촬영본의 앞 **35분 43초**가 접속 대기(4분 41초 무음) + 장비 체크 + 사전 잡담.

```
슬레이트  : 하나 둘 셋 · 박수 · 시작하겠습니다 · 준비되면
NG/재시작 : 다시 갈게요 · 다시 한번 · 잠깐만 · 컷 · 끊고
오프닝    : 반갑습니다 · 소개해 주시면 · 모셨습니다
클로징    : 감사합니다 · 초대하도록 · 마무리
```
슬레이트 직후 NG가 있으면 **굿 테이크는 그 다음**이다. 앞 구간에 값어치 있는 대화가 섞였으면 **버리기 전에 알린다**(별도 클립 소재).

→ "본편 = A~B, 앞 N분은 준비 구간"을 보고하고 확인받는다.

## STEP 2 — 컷 구간 카테고리별 제안 (핵심 산출)

`proposals`를 **카테고리별로** 표에 담는다. 평면 목록으로 뭉치지 않는다 — 카테고리 단위 승인/거부를 위해서다.

| 카테고리 | 솔로 | 인터뷰 | 설명 |
|---|---|---|---|
| `duplicates` 반복/재테이크 | ✅ 권장 | ❌ **거부 권장** | 인터뷰는 재테이크가 없다 |
| `pauses` 문장 사이 정적 | ✅ 권장 | ⚙️ 임계값 선택 | 0.6~5초 빈 구간 |
| `fillers` 군더더기 | ○ 옵션 | ○ 옵션 | `removeFillers:true`일 때만 |
| `intro` / `outro` 여백 | ❌ 보류 | ❌ 보류 | 타이틀·아웃트로 자리 |
| `longGaps` 긴 정적(5초+) | ⚠️ 내부 분석 | ⚠️ 내부 분석 | STEP 2.5 |

### ⚠️ 인터뷰에서 `duplicates`는 오탐이다 (실측)
117컷 제안 중 대부분이 **대화 연결어**였다:
> `"아 LI가 | 이제 | 모든 걸"` · `"안 해봤대요 | 그래서 | 근데"` — 중앙값 0.62초, 1초 미만이 130개
> 심지어 **굿 테이크 첫 마디**가 NG와 중복이라 잡혀서, 적용하면 오프닝이 날아간다.

→ 인터뷰면 **전부 거부**를 기본으로 제시하고, 길이 상위 몇 개만 자막·프레임으로 개별 검증.

### `pauses`는 임계값을 선택지로 준다
제거 길이 분포를 계산해 3안으로 제시(실측 예):

| 옵션 | 컷 수 | 절감 | 체감 |
|---|---|---|---|
| 전부 | 396컷 | 5.4분 | 대화 리듬 손상 위험 |
| **0.8초 이상만** | 133컷 | 3.1분 | **인터뷰 권장** |
| 1.0초 이상만 | 91컷 | 2.5분 | 보수적 |

**그 외 개선 구간**(알림음·인터럽션)은 자막을 직접 읽어 추가 지목. 실측: `"띵띵이 소리가 대표님 컴퓨터에서 나는 건가요?"` 21초 — MCP가 못 잡는다.

→ 표 전달 후 **"어느 카테고리를 삭제할까요?"** 로 멈춘다. 주 게이트다.

## STEP 2.5 — longGaps 내부 분석 (freeze + 프레임 diff)

> ⚠️ **longGaps를 통째로 보존/삭제하지 말 것.** 한 갭 안에 "화면 갱신"과 "정지 대기"가 섞여 있다.

**① freeze 구간 추출**
```bash
ffmpeg -hide_banner -ss <gap시작> -t <gap길이> -i <mediaPath> \
  -vf "freezedetect=n=-50dB:d=1.0" -map 0:v -an -f null - 2>&1 | grep freeze
```
> ⚠️ **웹캠 합성 화면에서는 freezedetect가 무용하다.** 참가자 타일이 늘 움직여 freeze가 안 잡힌다. 이땐 ③으로 바로.
> ⚠️ **zsh에서 `set -- $VAR` 워드분할이 안 된다.** 루프 인자는 python으로. 조용히 틀린 결과가 나온다.

**② 트림안 계산** — `컷 = [a+1.2s, b-0.4s]`, 컷 길이 ≥ 1.0s일 때만

**③ 프레임 diff — 임계값을 콘텐츠로 보정한다** ★
```bash
ffmpeg -ss <t> -i <src> -frames:v 1 -vf "crop=iw*0.72:ih:0:0,scale=192:108,format=gray" -f rawvideo -
```
**고정 임계값(diff<4=정지)을 쓰면 오판한다.** 실측 보정값:

| 콘텐츠 | 화면 전환 diff | 진짜 정지 diff | 임계 |
|---|---|---|---|
| 흰 배경 웹페이지 | **≈ 3.3** | ≈ 0.05 | **0.3** |
| 터미널·다크 UI | ≈ 15~130 | ≈ 0.0 | 4.0 |

→ 같은 갭에서 **"확실히 다른 두 프레임"을 먼저 재서 스케일을 잡고** 임계를 정한다. 큰 홀드는 시작|끝 프레임을 `hstack`으로 붙여 눈으로도 확인.

**화면 이동·무음 = 시연 → 배속 후보 (삭제 아님).** MCP에 속도 툴이 없으므로 구간·배율 표로 수동 안내.

**비용 원칙:** 자막으로 갭을 좁힌 뒤 그 구간만 본다. 전체를 프레임 스캔하지 않는다.

## STEP 2.6 — 컷 경계 파형 검증 ★ (모든 컷 공통)

**Whisper 세그먼트 경계는 부정확하다.** 단어 앞뒤에 100~600ms 여유가 붙는다.
컷 확정 전 모든 IN/OUT의 **±60ms RMS**를 잰다.

```python
# cut.wav(16kHz mono) 기준
# < -45dB 무음 ✅ / -45~-36dB 잔향 ○ / > -36dB 발성중 ⚠️
```
- **⚠️면 말이 잘린다.** 앞뒤 0.5초를 0.05초 간격으로 스캔해 무음 골짜기로 옮긴다.
- 반대로 Whisper가 "말이 있다"고 해도 **실측 -90dB면 잘려도 무손실**이다. 실측: `"네 반갑습니다"` 앞 1.0초 트림이 전부 무음이었다.
- 컷이 많으면 **전 경계를 표로 일괄 검증**(16개 경계 전수 검사 사례).

## STEP 3 — 컷 분할 + 삭제 (승인된 것만)

```
apply_timeline_removals(sequenceId, removals:[{start,end}...],
   sourceTimes:true, sourceMediaPath:<mediaPath>,   # 스팬이 소스시각이면 필수
   backup:false,        # 진입 전 backup_sequence 했으면 false
   dryRun:true)         # dryRun → skippedCount:0 확인 → dryRun:false
```
- **`sourceTimes:true`가 핵심.** analyze/freeze 스팬은 전부 소스-클립 시각이다.
- **이미 편집된 시퀀스를 추가로 자를 땐 `sourceTimes:false` + 타임라인 시각**이 안전하다(클립이 잘게 쪼개져 소스 매핑이 다의적일 수 있음).
- **프레임 양자화**: 프리미어는 `round(t*FPS)`로 스냅한다. 예상 길이를 이 규칙으로 계산해야 실측과 소수점까지 맞는다.
- 실행 후 **`verify` 확인**(판정 원칙 참조).

**연속 패스 원칙:** 한 번에 완벽히 못 잡는다. 1차(재테이크+정적) → 2·3차(정지-홀드)로 나누고 매번 STEP 4.

**맨 앞 리더(선행 빈 공간):** ripple이 흡수 못 한다. → **렌더 시작점 지정**으로 처리.

**인트로/아웃트로 여백은 자르지 않는다.** 사용자가 명시할 때만.

## STEP 3.5 — 구간 삽입 (콜드오픈·복원·B롤)

```
insert_clip(sourceMediaPath, sourceIn, sourceOut, timelineAt,
            mode:"insert", videoTrackIndex:0, audioTrackIndex:0)
```
- `mode:"insert"` = 뒤가 리플로 밀림(덮어쓰지 않음) / `"overwrite"` = 제자리 교체
- **타깃은 V1/A1(index 0).** 상위 트랙에 얹으면 아래 오디오와 겹쳐 들린다.
- 삽입 전 **STEP 2.6으로 경계 파형 검증**을 반드시 한다.
- 실행 후 `verify.gapCount:0` + `videoGrewBySec`이 요청 길이와 일치하는지 확인.

> 이 툴은 2026-08-03 신설이라 **실기 검증이 얕다.** 처음 쓸 때는 짧은 구간으로 시험하고 `verify`를 꼼꼼히 본다. 이상하면 사용자에게 수동 삽입 좌표(소스 TC + 삽입 지점 TC + `,` Insert 키)를 넘기는 쪽으로 후퇴한다.

## STEP 4 — 실측 검증

`list_sequence_tracks(includeSourceTimes:true)` 재조회:
- `verify.measuredEndSec` == 예상 길이 (프레임 양자화 반영, ±0.1초)
- `verify.gapCount: 0` ← 리플 실패 탐지
- `verify.avParity: true` ← V/A 클립 수·끝 일치
- `list_sequences` 스냅샷을 STEP 0과 비교(다른 시퀀스 드리프트)

불일치면 **정지·보고**. 자동 복구·재시도 금지.

## STEP 5 — 자막으로 인계

편집이 확정되면 **`자막-검수` 스킬**로 넘긴다. 여기서 자막을 만들지 않는다.
STEP 1의 `analysis.json`과 `cut.wav`를 그대로 넘기면 재전사 없이 진행된다.

## 저장

**자동 저장하지 않는다.** 검증 리포트 후 사용자가 "저장"이라고 할 때만 `save_project`.

## 알려진 도구 결함

| 도구 | 결함 | 대응 |
|---|---|---|
| `list_sequences` `duration` | **편집 중 과도 상태 반환** | 판정은 `list_sequence_tracks.verify.measuredEndSec` |
| `undo` | 2회분만 되돌리고 이후 무동작 | 안전망으로 전제 금지. **프리미어 `Cmd+Z`가 더 깊고 정확** |
| `trim_clip` | 축소 전용, 헤드 복구 불가 | 헤드/테일은 애초에 자르지 않음 |
| `apply_timeline_removals` | 백업 시퀀스 이름이 응답값과 다름 | `list_sequences`로 실제 이름 재확인 |
| `apply_timeline_removals` | **선행 빈 공간(리더) 흡수 못 함** | 렌더 시작점 지정으로 처리 |
| `move_clip` | **리플 없음** — 중간 검은 깜빡임 | 리더 제거·전체 시프트에 쓰지 말 것 |
| 클립 속도(배속) 툴 | **없음** | 구간·배율 표로 수동 안내 |
| `list_sequence_tracks` | 클립 수백 개면 토큰 초과 | `compact:true` |
| 시퀀스 길이 드리프트 | 안 건드린 시퀀스 변동 사례 | STEP 0/4 스냅샷 비교 |

> **MCP 버전 주의:** `insert_clip`·`includeSourceTimes`·`verify`는 2026-08-03 추가분이다. 툴 목록에 안 보이면 MCP 서버가 구버전이다 — `npm run build` 후 클라이언트 재시작이 필요하다.

## 실수하기 쉬운 것

- **타임라인이 3개 이상이면 헷갈린다.** 백업이 쌓이면 전부 `시퀀스 01 복사`가 된다. 작업 전 **ID와 길이로** 대상을 특정하고 이름 변경을 권한다.
- **소스 시각 60초 오차.** `83:03`을 `5043`으로 계산한 실수가 실제로 났다(`83*60+3=4983`). 타임코드↔초 변환은 반드시 코드로.
- **삭제 전 승인이 유일한 방어선이다.** undo는 못 믿는다.
